# Labasa Yaqona Portal

A lightweight web portal connecting yaqona (kava) farmers with buyers and exporters in Labasa, Cakaudrove and the wider Vanua Levu region of Fiji.

The portal is an **information and communication tool only**. It does not process payments, certify product quality, replace traditional trading, or replace the Fiji Kava Standard.

## Features

- Farmer, buyer, exporter and administrator roles.
- Registration with pending-account approval; administrators can approve, reject or deactivate accounts.
- Password hashing, session login, CSRF protection and role-checked routes.
- Farmer listings with kava type, quantity, unit, drying status, location, asking price and description.
- Listings are private to the public until approved. New and edited listings return to the review queue.
- Search by keyword, location, type, drying status and price range, with pagination.
- Listing details and farmer profile information.
- Buyer/exporter enquiries and saved conversation replies.
- Indicative monthly price guide, table and lightweight chart.
- Administrator dashboard for account moderation, listing moderation and price guide management.
- Responsive mobile-first design, no paid APIs or external assets.

## Requirements

- Python 3.10 or later recommended.
- A modern browser.
- No external database server or paid service is required.

## Install and run locally

### 1. Extract the project

Extract the ZIP file, then open a terminal in the `labasa-yaqona-portal` folder.

### 2. Create a virtual environment

Windows PowerShell:

```powershell
py -m venv .venv
.venv\\Scripts\\Activate.ps1
```

Windows Command Prompt:

```bat
py -m venv .venv
.venv\\Scripts\\activate.bat
```

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Create the database and demo data

```bash
python seed.py
```

This creates `portal.db`, the schema, sample accounts, listings, an enquiry and sample price-guide entries. It is safe to run again: it avoids duplicate demo accounts and sample entries.

### 5. Start the website

```bash
python app.py
```

Open <http://127.0.0.1:5000> in your browser.

To stop the server, press `Ctrl+C`.

## Typical walkthrough

1. Log in as admin and review the pending farmer example or any new registration.
2. Log in as a farmer and create a listing. It starts in **Pending** status.
3. Log in as admin and approve the listing. It then appears in Browse Kava.
4. Log in as a buyer or exporter and open the listing detail page.
5. Send an enquiry, then log back in as the farmer to reply.
6. Use the Admin dashboard's Price Guide section to add or delete indicative monthly entries.

## Database tables

- `users`: identity, account type, profile, password hash and approval status.
- `listings`: farmer supply posts and moderation status.
- `enquiries`: conversation thread linking a listing, buyer and farmer.
- `messages`: saved messages and replies.
- `price_guide`: indicative prices by kava type and month.

SQLite foreign keys are enabled. Indexes support common account, listing, and conversation lookups. Search is paginated.

## Security and production checklist

This project is a functional starter application, not a formally security-audited production service. Before public launch:

1. Set a long random `SECRET_KEY` environment variable. Never deploy using the development fallback.
2. Use HTTPS and set `COOKIE_SECURE=1`.
3. Use a production WSGI server (for example, Waitress on Windows or Gunicorn on Linux) rather than Flask's development server.
4. Add login rate limiting, email verification and a password-reset process before real public use.
5. Review account recovery, administrator permissions, audit logging, backups, privacy terms and retention requirements.
6. Add automated tests and have a developer perform a security review.
7. Back up `portal.db` regularly and test restore procedures. Do not keep the only database copy on an ephemeral hosting disk.
8. Keep all dependencies updated and protect the server and environment variables.
9. Use real market information only with clear sources, dates, units and disclaimers.

### Environment variables

- `SECRET_KEY`: secret used to sign sessions and CSRF tokens.
- `DATABASE_PATH`: optional path to the SQLite database.
- `COOKIE_SECURE=1`: mark session cookies as HTTPS-only.
- `PORT`: optional local listening port.

Example (macOS/Linux):

```bash
export SECRET_KEY="replace-with-a-long-random-secret"
export COOKIE_SECURE=1
```

Example (PowerShell):

```powershell
$env:SECRET_KEY = "replace-with-a-long-random-secret"
$env:COOKIE_SECURE = "1"
```

## Cheap deployment options

- **Lowest cost:** run it on a trusted computer or small office PC for a limited pilot. Keep it powered on, backed up, and protected. This is not ideal for a public marketplace.
- **Low-cost public hosting:** use a small Python-capable VPS or a reputable platform's low-cost Python web service. Check current pricing, sleep/usage limits, persistent storage, and whether SQLite files survive redeployments before choosing.
- **For a multi-user public launch:** use a platform with persistent storage and HTTPS. Consider PostgreSQL rather than SQLite if write traffic grows or multiple application instances are required.

No paid third-party APIs are used by the app itself. Domain registration and hosting may still cost money. Confirm the provider's current terms and costs before deployment.

## Known scope boundaries

- No online payments, SMS service, export paperwork, native mobile app, quality sensors or AI price prediction.
- Demo data and demo credentials are not production data.
- Price-guide values are illustrative sample values and must not be represented as official market prices.
- The portal does not independently verify user identity, quantities, product quality, or compliance with the Fiji Kava Standard.
